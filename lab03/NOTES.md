git diff показывает различия между состояниями репозитория, git show выводит детали и изменения конкретного коммита, а git log отображает историю коммитов — список с метаданными, который можно фильтровать и дополнять патчами или статистикой.

git log -S ищет коммиты, в которых изменилось количество вхождений заданной строки, а git blame показывает, кто и в каком коммите последним изменил каждую строку файла.



git restore без параметров по умолчанию берёт состояние файлов из HEAD (последнего коммита) и восстанавливает их в рабочей директории и/или в индексе — в зависимости от других флагов.



git restore --source=… в Git обозначают текущую директорию, а не источник состояния; --source ожидает ссылку на коммит (например, HEAD, HEAD\~1, хэш, ветку).



git revert создаёт новый коммит, который отменяет изменения, но оставляет историю нетронутой — поэтому он безопасен для опубликованной ветки. В отличие от него, git reset --hard жёстко удаляет последующие коммиты и переписывает историю — это опасно в общем репозитории, потому что ломает локальные ветки у других разработчиков.



Ветка (branch) — динамическая ссылка на коммит; смещается при новых коммитах, служит линией разработки.

Тег (tag) — статичная метка на конкретном коммите; не двигается, применяется для релизов/версий.
